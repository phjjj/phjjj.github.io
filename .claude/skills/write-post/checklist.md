# 블로그 글쓰기 체크리스트

Oct 6, 2026 · @해준

## 사용법

글 하나를 쓸 때마다 이 문서를 1단계부터 4단계까지 순서대로 한 번씩 훑는다. 단계마다 쓰는 시점이 다르다.

| 단계 | 언제 여나 | 걸리는 시간 | 남기는 것 |
| --- | --- | --- | --- |
| 1. 글감 찾기 | 뭘 쓸지 모를 때, 작업을 막 끝냈을 때 | 5분 | 주제 한 줄 |
| 2. 목표 정하기 | 초고 쓰기 직전 | 5\~10분 | 다섯 질문의 답 |
| 3. 핵심 문장 두 개 | 초고 쓰기 직전 (2단계 바로 뒤) | 5분 | 문장 두 개 |
| 4. 퇴고 | 초고를 다 쓴 뒤 | 10\~20분 | 고친 문장 |

2·3단계 답은 초고 파일 맨 위에 주석으로 붙여 두고 발행 전에 지운다. 쓰다가 방향을 잃으면 그 두 문장으로 돌아와 넣을지 뺄지 정한다.

## 1단계: 글감 찾기

"왜 이걸 만들었나"는 누구나 쓸 수 있는 글감이다. 필터 옵션 하나든 서비스 전체든 규모만 다를 뿐이고, 아래 질문 중 하나에만 답해도 글 한 편이 된다.

방금 끝낸 작업(PR, 배포, 장애 대응, 리팩터링)을 떠올리고 답이 길게 나오는 질문을 고른다.

- [ ] 지금 상황의 문제는 무엇인가?
- [ ] 잘 돌아가서 그대로 둬야 하는 것은 무엇인가?
- [ ] 같은 문제를 풀려던 이전 시도는 무엇이었나?
- [ ] 기존 방식이 안 통하게 된 최근 변화는 무엇인가?
- [ ] 이상적인 해결책은 어떤 모습이고, 그걸로 사람들이 무엇을 할 수 있게 되나?
- [ ] 기술 목표와 지키려는 원칙은 무엇인가?
- [ ] 어떻게 구현할 것인가?
- [ ] 누가 가장 관심을 가질까?
- [ ] 사용자는 이걸 어떻게 쓸까?
- [ ] 얼마나 나아졌는지 어떻게 측정할까?

**남길 것:** 주제 한 줄 (예: "검색 API에 날짜 필터를 넣은 이유")

## 2단계: 목표 정하기

글에는 글쓴이, 독자, 주제 세 요소가 있다. 보통은 '나와 주제'만 생각하지만, '독자와 주제'(독자가 이 주제를 얼마나 아나)와 '나와 독자'(왜 내 말을 들어야 하나)도 따져야 한다.

초고 쓰기 전에 아래 표의 빈칸을 채운다. 한두 줄이면 충분하다.

| # | 질문 | 내 답 |
| --- | --- | --- |
| 1 | 누가 읽길 바라는가? |  |
| 2 | 그들은 이 주제를 얼마나 아는가? |  |
| 3 | 그들은 왜 이 주제에 관심을 가지는가? |  |
| 4 | 내 관점이 왜 그들에게 주목받을 만한가? |  |
| 5 | 읽고 나서 그들의 생각이나 행동이 어떻게 바뀌길 바라는가? |  |

2번 답이 독자 수준을 정한다. 용어를 설명할지, 배경을 얼마나 깔지가 여기서 갈린다.

## 3단계: 핵심 문장 두 개

본문에는 넣지 않는 문장 두 개를 반드시 적고 나서 초고를 시작한다. 책이 가장 강하게 "건너뛰지 말라"고 하는 단계다.

| 문장 | 무엇을 바탕으로 쓰나 | 언제 다시 보나 | 내 문장 |
| --- | --- | --- | --- |
| 이 글의 목표는? | 2단계 1번(독자) + 5번(바라는 변화) | 넣을지 뺄지 고민할 때, 리뷰 부탁할 때 |  |
| 내 관점이 흥미로운 이유는? | 2단계 3·4번 | 같은 주제의 다른 글, AI가 쓴 글과 비교할 때 |  |

예시 형식: "사내 백엔드 개발자가 이 글을 읽고 날짜 필터를 직접 붙일 수 있게 한다." / "공식 문서는 사용법만 다루지만, 나는 운영 중 겪은 실패를 바탕으로 설명한다."

## 4단계: 퇴고

장황한 문장은 코드로 치면 비대해진 코드다. 초고는 지저분해도 괜찮고, 퇴고에서 아래 네 유형만 골라 고친다. 한 문장이 여러 유형에 걸릴 수도 있다.

- [ ] **너무 긴 문장:** 소리 내 읽다가 숨이 차면 둘로 나눈다.
- [ ] **전치사·조사가 줄줄이 붙은 문장:** "\~부터 \~에 걸쳐 \~에 대해"처럼 수식이 겹치면 핵심만 남긴다.
- [ ] **힘 빠진 수동태:** "버그가 발견되었다"보다 "버그를 찾았다"가 낫다.
- [ ] **행위자·동작이 흐릿한 문장:** 누가 무엇을 했는지 바로 보이게, 주어와 동사를 가까이 둔다.

찾는 요령: 초고를 소리 내 한 번 읽고, 걸리는 문장에 표시만 한 뒤 한꺼번에 고친다.

## 출처

『개발자가 블로그도 써야 하나요?』를 요약·재구성했다. 1단계는 2.2.17 제작 이유(p.73), 2단계는 4.2.3 목표 정의하기(p.110), 3단계는 두 가지 핵심 문장(p.112), 4단계는 5.3.1 불명확하고 장황한 문장 가려내기에서 가져왔다.
